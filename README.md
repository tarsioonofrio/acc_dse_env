# acc_dse_env — CNN Accelerator DSE Environment (Capstone / TCC)

This repository is my undergraduate capstone (TCC): a reproducible environment to explore a CNN accelerator flow, connecting:
**CNN configuration/training -> data export -> RTL/BRAM generation -> simulation/synthesis artifacts**.

## Highlights

- End-to-end flow from CNN configs to generated RTL/BRAM initialization files
- Organized experiment outputs under `experiments/`
- Includes simulation and synthesis collateral (scripts, reports, and analysis folders)

## Quickstart (use existing default artifacts)

1. Create the Python environment:

```bash
conda env create -f environment.yaml
conda activate acc_dse_env
```

2. (Optional) Train a CNN:

```bash
python apps/cnn-train-cifar10.py -n <cnn_config.json>
```

3. Generate RTL + BRAM files:

```bash
python apps/rtl-generate.py -n <cnn_config.json> -w <rtl_config.json>
python apps/bram-generate.py -n <cnn_config.json> -w <rtl_config.json>
```

4. Simulate using the provided scripts (see the Simulation section below).

## Repository organization

* `apps/`: `python` scripts to train a basic deep learning model and generate RTL code.
  * `bram-generate.py`: generate BRAMs needed to run trained CNN model in FPGA.
  * `cnn-train-cifar10.py`: training script for a simple CNN model.
  * `rtl-generate.py`: generate RTL code needed to run trained CNN model.
  * `table-generate.py`: generate data tables for CNN weights and feature maps.
* `experiments/`: output files generated by scripts in `apps/`.
  * `cnn_config`: JSON files used to configure CNN models.
  * `cnn_output`: output data from trained CNN models. Pattern: `experiments/cnn_output/cnn_json_name/`.
  * `rtl_config`: JSON files used to configure RTL and BRAM generation.
  * `rtl_output`: generated RTL and BRAM files. Pattern: `experiments/rtl_output/cnn_json_name/rtl_json_name/`.
    * `bram/`: BRAM RTL code and support files.
    * `core/`: Core support files.
    * `layer/`: Layer files (weights, feature maps, and support data).
    * `samples/`: Input sample data in `txt` and RTL formats.
    * `table/`: Data tables in `csv`, `json`, and `txt`.

* `cacti/`
* `lsynth/`
* `power_analyses/`
* `psynth/`
* `qshift/`
* `rtl/`: accelerator component HDL code.
* `scripts/`: auxiliary scripts.
* `sim_coroutine/`: RTL simulation flow scripts (makefiles + runner).
* `sim_netlist/`: scripts for netlist simulation with 28 nm technology.
* `test/`: `cocotb` scripts.

## Tutorial

### Training

If you do not want to train a network from scratch, you can skip this part.

First, configure the neural network: copy `default.json` in `experiments/cnn_config` and change the settings and file name.
Then train and save weights with:

`python apps/cnn-train-cifar10.py -n {cnn json config filename}`

In `experiments/cnn_output`, a folder with the chosen name will be created to store network weights.

### Generation RTL and BRAMs

There are already auxiliary files in the repo. If you do not want to generate new ones, you can skip this part.

Similar to the previous step, `experiments/rtl_config` contains HW configuration files.
Copy `default.json`, change settings and filename, then run:

`python apps/rtl-generate.py -n {cnn json config file name} -w {rtl json config file name}`

and

`python apps/bram-generate.py -n {cnn json config file name} -w {rtl json config file name}`

In `experiments/rtl_output`, a folder named `{cnn file name}/{rtl file name}` will be created with simulation support files per layer, including:

* Generics.
* Package with `type_config_*` `record` used to configure the convolutional layer.
* Input feature map (`ifmap`), input weights (`iwght`) and gold output feature map in VHDL and TXT.

Other files required for `core` simulation are saved in the `core` folder.

### Simulation

The RTL simulation flow is in `sim_coroutine/`, using makefiles and `run.sh`.
Examples include `cnn.makefile`, `core_serial.makefile`, and `sys2d_ws.makefile`.

If you want to use a new CNN model or RTL configuration, update paths like:

     ../experiments/rtl_output/default/default/core/config_pkg.vhd
     ../experiments/rtl_output/default/default/core/generic_file.txt

If you want to run a core or convolutional layer using layer index `1` instead of `0`, change:

     ../experiments/rtl_output/default/default/0/config_pkg.vhd

to:

     ../experiments/rtl_output/default/default/1/config_pkg.vhd

If you want to use other RTL settings, change `default/default` to the desired project folder and keep all related paths aligned.

regarding an entire system. Thus, one of the future works is to extend the proposed frameworks to 
cover systems  composed of CPUs, DMA, and CNN accelerators, for example, as illustrated in 
Figure 7.1. Also, it is possible to combine the system simulator with the analytic flow to 
improve the  accuracy of the PPA results, like clock cycles estimation. 
Thus, we proposed the following future works:

* **Accelerator Design.** Extend the set of accelerators and functions implemented in hardware.
